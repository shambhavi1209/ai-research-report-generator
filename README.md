# AI Research Report Generator

Minimal web app that takes a company's financial context document (PDF / CSV / TXT)
and returns a downloadable, auto-filled Geojit "Retail Equity Research" report PDF
(teal theme, matched to the provided Eternal Ltd. sample) — same layout: rating
header, company-data sidebar, shareholding, result highlights, quarterly financials
with YoY/QoQ, consolidated financials, charts, and outlook narrative.

## How to run

```bash
pip install -r requirements.txt
export GEMINI_API_KEY=your_key         # free key at https://aistudio.google.com
streamlit run app.py
```

Windows: WeasyPrint needs the GTK3 runtime — install
`gtk3-runtime-*-win64.exe` from github.com/tschoonj/GTK-for-Windows-Runtime-Environment-Installer,
then run `set PATH=C:\Program Files\GTK3-Runtime Win64\bin;%PATH%` before `streamlit run app.py`.
Linux: `sudo apt install libpango-1.0-0 libpangocairo-1.0-0`.

Then: enter the company name → upload the context document → Generate report →
Download PDF. Toggle **Demo mode** in the sidebar to run without an API key
(built-in sample data, so the full pipeline can be tested offline).

Headless CLI:

```bash
python generate.py --file input.pdf --company "Company Ltd" --out report.pdf
```

## Architecture
upload (pdf/csv/txt)
└── extractors/ → plain text (+ tables flattened)
└── llm/extract.py → Gemini 3.5 Flash, structured output → schema.ResearchReport
├── charts/builders.py → matplotlib PNGs (base64)
└── render.py → Jinja2 fills templates/report.html → WeasyPrint → PDF
app.py = Streamlit UI · generate.py = headless CLI
## Where the template fields are defined

**One file: `schema.py`.** Every field in the PDF is a Pydantic field there; the same
schema is passed to Gemini as its structured-output contract, so the model cannot
return fields the template doesn't know about.

| schema.py | Template location |
|---|---|
| `rating`, `headline`, `company_data.cmp/target_price` | Header rating block (upside % computed, never extracted) |
| `company_data.*` | Header strip + sidebar "Company Data" box |
| `shareholding`, `price_performance` | Sidebar boxes |
| `company_description`, `result_highlights` | Main column p.1; `analysis_points` → p.2 "Key highlights" |
| `financials[]` | Sidebar "Y.E March" table + p.2 "Consolidated Financials" + annual chart |
| `quarterly[]` | "Quarterly Financials Consolidated" (YoY/QoQ computed in render.py, never extracted) + charts |
| `outlook_valuation` | "Outlook & Valuation" |

### Adding a new field (3 steps)
1. Add it in `schema.py` (Optional, default None, with a `description` — the description doubles as the LLM instruction).
2. If needed, add a rule in `llm/extract.py`'s prompt.
3. Reference it in `templates/report.html`, e.g. `{{ report.company_data.beta | fmt(2) }}`.

## Design decisions

- **HTML + Jinja2 + WeasyPrint over ReportLab** — the sample is a dense multi-column
  layout; recreating it declaratively in CSS is faster and keeps template and data separated.
- **Hallucination guardrails** — the prompt requires `null` for anything not in the
  document; **rating and target price are never invented**. Structured output pins the
  JSON to the schema; temperature 0.2. Growth percentages and margin deltas are
  **computed in code from extracted values**, never asked of the LLM.
- **Missing fields degrade gracefully** — every field is Optional; None renders as "—",
  empty sections collapse (see the ICICI example).
- **Long documents** — inputs beyond ~400k chars are reduced by keeping paragraphs
  densest in financial keywords, order preserved.
- **Units** — the prompt normalises ₹ million/lakh to ₹ crore (verified on LTTS: ₹29,795 mn → 2,980 cr).

## Examples (`examples/`, generated by this pipeline from the provided test docs)

- **LTTS_example.pdf** — from the L&T Technology Services Q2FY26 press release +
  investor deck. Full extraction: revenue 2,980 cr, PAT 329 cr, QoQ growth computed,
  and correctly **NOT RATED** with no target — the source states neither.
- **ICICI_example.pdf** — from the ICICI Bank Q2-2026 investor presentation. A bank
  doesn't fit a corporate P&L template, so many fields are legitimately "—": this is
  the graceful-missing-data path on a real document. Closest real metrics (core
  operating income, PAT, EPS) are extracted and traceable to the deck; nothing is invented.

Demo-mode data (`demo_data.py`, `sample_inputs/`) allows offline testing without an API key.

## Limitations / next steps

- Scanned (image-only) PDFs would need an OCR pass in `extractors/`.
- Banks/insurers deserve a sector-specific schema (NII, NIM, GNPA) — the current
  schema targets non-financial corporates.
- Peer-comparison and balance-sheet/cash-flow pages of the sample are not yet
  templated; the schema/section pattern extends to them directly.
- A per-field `source_snippet` for click-through verification is the natural next step.
